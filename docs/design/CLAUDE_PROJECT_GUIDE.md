# Claude Project: Storefront Design

## Налаштування

Створіть у Claude Project з назвою `Storefront Design` і додайте в Knowledge:

1. `DESIGN_BRIEF.md`;
2. `UI_DECISIONS.md`;
3. брендбук;
4. Figma-посилання або скріншоти чинних header і footer;
5. дані та медіа 3–5 реальних товарів.

Не додавайте весь backend-репозиторій: він не є джерелом дизайну storefront.

## Інструкції проєкту

```text
Ти senior e-commerce product designer і frontend designer. Працюй лише з
матеріалами цього Project. DESIGN_BRIEF.md і UI_DECISIONS.md — джерела правди.

Брендбук є єдиним джерелом кольорів, типографіки та візуального характеру.
Не вигадуй нову палітру, бренд-стиль або шрифти. Збережи наявні header/footer:
зміни до них дозволені лише після окремого обґрунтування та погодження.

Веди роботу по одному екрану. Спершу коротко подай структуру екрана,
UX-ризики й перелік повторно використовуваних компонентів. Потім створи
desktop і mobile дизайн. Не пиши код, доки користувач явно не затвердить
дизайн. Після затвердження генеруй лише код поточного екрана та потрібних
компонентів.

Застосовуй WCAG 2.2 AA. Якщо бракує не критичних даних, зроби найменше
розумне припущення і винеси його в кінцевий список; не розширюй завдання на
інші екрани.
```

## Стартовий запит для екрана

```text
Екран: [назва].
Мета користувача: [дія / результат].

Працюй у межах матеріалів цього Project. Використовуй брендбук як єдине
джерело стилю та збережи наявні header/footer.

Спочатку дай стисло:
1. структуру екрана;
2. UX-ризики;
3. список компонентів, які можна повторно використати.

Потім створи дизайн desktop і mobile. Поки що не пиши код і не проєктуй інші
сторінки. Якщо даних бракує, зроби найменше розумне припущення та познач його
наприкінці.
```

## Запит після погодження дизайну

```text
Дизайн екрана «[назва]» затверджено. Згенеруй лише адаптивний код цього
екрана та потрібних перевикористовуваних компонентів. Не змінюй header/footer
без окремого обґрунтування. Використовуй токени й правила з UI_DECISIONS.md.
```

## Контроль ліміту

- Відкривайте новий чат для кожного екрана в межах цього Project.
- Не повторно прикріплюйте ті самі джерела поза Project.
- Для звичайного дизайну не вмикайте Research, вебпошук чи extended thinking.
- Перед великим екраном перевіряйте `Settings → Usage`.
- Якщо потрібна жорстка межа витрат, не підключайте API credits.

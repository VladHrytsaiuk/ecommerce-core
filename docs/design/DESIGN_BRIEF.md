## Бренд і наявний інтерфейс

- **Брендбук:** додати PDF, Figma або посилання в Knowledge проєкту.
- **Header:** додати Figma-посилання або скріншоти поточної реалізації.
- **Footer:** додати Figma-посилання або скріншоти поточної реалізації.
- **Правило:** брендбук — єдине джерело кольорів, типографіки та характеру
  дизайну. Не змінювати header/footer без окремого погодження.

## Обов'язкові принципи

- Один чат — один екран. Не проєктувати інші екрани без прямого запиту.
- Спершу UX-структура й ризики, потім desktop та mobile дизайн, і лише після
  погодження — код.
- Використовувати реальні дані: назви товарів, ціни, категорії та медіа з
  прикладених матеріалів; не вигадувати бренд або товари.
- Нові компоненти мають бути перевикористовуваними; затверджені рішення
  фіксуються в `UI_DECISIONS.md`.
- Дотримуватись WCAG 2.2 AA: контраст, видимий focus, семантичні назви,
  керування з клавіатури й достатні touch-цілі.

## Формат результату для кожного екрана

1. Коротка структура екрана, UX-ризики та список повторно використовуваних
   компонентів.
2. Адаптивний дизайн desktop і mobile у межах затвердженої дизайн-системи.
3. Після явного погодження — лише код цього екрана і необхідних компонентів.
4. Стислий список припущень, якщо без них неможливо рухатись далі.

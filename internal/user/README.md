# Модуль користувача (User Module)

Даний проектний модуль відповідає за автентифікацію, управління профілями користувачів та збереження адрес доставки (Нова Пошта).

## Архітектура

Модуль побудований за принципом **Clean Architecture**, що забезпечує чітке розділення відповідальностей:

1.  **Domain Layer** (`internal/user/domain/`): 
    *   Містить основні бізнес-сутності (`User`, `Session`, `UserAddress`).
    *   Визначає інтерфейси (контракти) для репозиторіїв та сервісів.
    *   Визначає доменні помилки (`ErrUserNotFound` тощо).
    *   **Це ядро модуля**, воно не залежить від зовнішніх бібліотек (крім gorm для тегів).

2.  **Repository Layer** (`internal/user/repository/postgres/`):
    *   Імплементація інтерфейсів домену за допомогою **GORM** та **PostgreSQL**.
    *   Відповідає за фізичне збереження даних та обробку помилок бази даних (наприклад, унікальність пошти).

3.  **Service Layer** (`internal/user/service/`):
    *   Містить бізнес-логіку: реєстрація, логін, перевірка паролів, генерація JWT.
    *   Координує роботу декількох репозиторіїв.

4.  **Delivery Layer (HTTP)** (`internal/user/delivery/http/`):
    *   Обробка вхідних HTTP-запитів через фреймворк **Gin**.
    *   Валідація вхідних даних (DTO) та повернення JSON відповідей.

## Сутності БД (Database Entities)

### User (Таблиця `"user"`)
Основний запис користувача. Підтримує **Soft Delete** (запис не видаляється фізично, а лише помічається як видалений).
*   `email` та `phone` мають бути унікальними (див. міграцію `000003`).
*   Паролі зберігаються у вигляді хешу **bcrypt**.

### Session (Таблиця `session`)
Зберігає довготривалі **Refresh Tokens**.
*   Кожна сесія прив'язана до браузера/пристрою (`UserAgent`, `IP`).
*   Реалізовано механізм автоматичного видалення прострочених сесій.

### UserAddress (Таблиця `user_address`)
Збережені дані для доставки (Нова Пошта).
*   Один користувач може мати декілька адрес.
*   Тільки одна адреса може бути помічена як `is_default` (основна для замовлень).

## Міграції

Для цього модуля використовуються наступні SQL-міграції:
1.  `000001_init_schema`: Створення таблиці `"user"` та `user_address`.
2.  `000002_add_sessions`: Додавання таблиці сесій.
3.  `000003_add_unique_constraints`: Встановлення унікальності для пошти та телефону на рівні БД.
